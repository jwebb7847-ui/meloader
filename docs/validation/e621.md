### 2. Offline local-processing benchmark

```sh
go test ./internal/mapping -run '^$' -bench '^BenchmarkE621CategorizedLocalProcessing$' -benchtime=1x -count=3 -benchmem
```

This runs 200-, 1,000-, and 10,000-record local mapping loops; it does **not** fetch images or call e621. Report the `ns/op`, `B/op`, and `allocs/op` numbers. Because the benchmark reuses an in-memory metadata fixture, it establishes **local processing cost only**—not end-to-end throughput, concurrent network behavior, or performance on diverse real posts.

### 3. Check one real extractor payload without downloading media

From the same checkout, with gallery-dl available and configured as you ordinarily use it:

```sh
gallery-dl --dump-json 'https://e621.net/posts/535' > e621-validation.json
python3 - <<'PY'
import json
from pathlib import Path

messages = json.loads(Path("e621-validation.json").read_text())
posts = [msg[-1] for msg in messages
         if isinstance(msg, list) and msg
         and isinstance(msg[-1], dict)
         and msg[-1].get("category") == "e621"]
if not posts:
    raise SystemExit("No e621 metadata found; check gallery-dl output and access errors.")
post = posts[0]
categories = {k: len(v) for k, v in sorted(post.items())
              if k.startswith("tags_") and isinstance(v, list)}
print("source:", post.get("category"))
print("post id:", post.get("id"))
print("rating:", post.get("rating"))
print("categorized tag counts:", categories)
print("flat tag count:", len(post.get("tags", [])))
if not categories:
    raise SystemExit("WARNING: categorized tag fields absent; investigate before importing.")
PY
```

`--dump-json` requests metadata from e621, so this check **does access the internet**, but does not download the image media. Respect site rate limits. The example is the public post used in gallery-dl's upstream tests; it may become unavailable. If a request is refused, record the refusal rather than treating it as a taxonomy regression.

Avoid sharing the raw JSON if it contains private source URLs or other metadata you would rather not expose; the printed category/count summary is sufficient for this validation.

## Recorded local benchmark — 2026-11-13

Tested on an Apple M5 (`darwin/arm64`), using:

```sh
go test ./internal/mapping -run '^$' -bench '^BenchmarkE621CategorizedLocalProcessing$' -benchtime=1x -count=3 -benchmem
```

| Synthetic post count | Median elapsed time (3 runs) | Median time per post | Median allocated bytes / run | Median allocations / run |
| ---: | ---: | ---: | ---: | ---: |
| 200 | 1.663 ms | 8.31 µs | 467,304 | 14,407 |
| 1,000 | 6.200 ms | 6.20 µs | 2,182,504 | 72,007 |
| 10,000 | 34.940 ms | 3.49 µs | 21,672,744 | 720,047 |

The three 10,000-record timings were **42.810 ms**, **34.940 ms**, and **33.186 ms**. Thus the benchmark is encouraging but too short to infer low-variance performance. Repeated use of one fixture means this is **a microbenchmark of in-memory mapper calls**, not a diverse real workload, a test of retrieval, or a measure of user-perceived import speed. Allocated bytes over the operation do not equal peak memory consumption. A comparison to a known baseline and full source-to-library test remain necessary.

`go run`, `make build` and binary launch semantics need separate verification on each user's Mac. For tests involving running services, record both repository commit SHAs, both executable launch commands, and the configuration/data paths. Updating a checkout alone does not replace a running process.
